Section 01

Introduction & Organizational Context

During my cooperative education internship at the Geography Division, Royal Thai Survey Department (RTSD), I was entrusted with modernizing geographic data services. The department manages massive repositories of topographical, geodetic, and cadastral spatial layers critical for national mapping and security operations.

However, legacy internal spatial query systems suffered from severe architectural bottlenecks that crippled responsiveness during peak multi-user workloads. Specifically, the system exhibited two major pain points:

Per-Request Connection Overhead

Opening a fresh database TCP handshake and authentication sequence for every single incoming HTTP request saturated database workers, causing immense CPU context-switching overhead.

Timeouts & Connection Exhaustion

When more than 15 concurrent GIS analysts queried overlapping vector boundaries, unpooled connections hit PostgreSQL's `max_connections` ceiling, triggering catastrophic HTTP 504 Gateway Timeouts.

The core objective of my internship project was to engineer a high-throughput, container-ready Spatial API Server using FastAPI and PostGIS, capable of handling complex polygon containment queries and coordinate transformations under sustained concurrent loads without degrading performance.

Section 02

Engineering Solution & Implementation

To eliminate per-request connection overhead and ensure blazing-fast spatial calculations, I engineered four key architectural pillars into the FastAPI backend:

1

ThreadedConnectionPool with FastAPI Lifespan

Managing persistent database connection pooling across application lifecycle states.

Instead of instantiating `psycopg2` connections inside endpoint handlers, I utilized FastAPI's modern `@asynccontextmanager` Lifespan events to initialize a robust `ThreadedConnectionPool` upon server startup and safely drain connections on shutdown. 

from contextlib import asynccontextmanager
from fastapi import FastAPI
from psycopg2.pool import ThreadedConnectionPool

db_pool = None

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup: Initialize pool with optimized thread capacity
    global db_pool
    db_pool = ThreadedConnectionPool(minconn=5, maxconn=65, dsn=DATABASE_URL)
    yield
    # Shutdown: Close all pooled connections gracefully
    if db_pool:
        db_pool.closeall()

app = FastAPI(lifespan=lifespan)
2

Spatial Data Validation with PostGIS (`ST_Contains`)

Server-side geometric validation to verify point-in-polygon containment.

Client coordinates are checked against official administrative and topographical boundaries stored as geometry columns in PostGIS using optimized spatial SQL functions. 

-- Spatial SQL validation query utilizing ST_Contains
SELECT id, zone_name, ST_AsText(geom) 
FROM rtsd_boundaries 
WHERE ST_Contains(geom, ST_SetSRID(ST_Point(%s, %s), 4326));
3

Coordinate Transformations (`pyproj`)

Implemented precise transformation handlers converting WGS84 geographic coordinates (EPSG:4326) into local grid systems like UTM Zone 47N (EPSG:32647) for survey-grade accuracy required by RTSD mapping protocols.

4

Spatial Query Optimization (GiST Index)

Created generalized search tree indexes (CREATE INDEX idx_spatial_geom ON rtsd_boundaries USING GIST(geom);) which reduced spatial filter execution times from linear full-table scans down to O(log N) bounding-box tree lookups.

Section 05

Lessons Learned & Future Outlook

Key Learnings & Takeaways

  • Concurrency Management: Mastered asynchronous lifecycle hooks in FastAPI and the critical necessity of proper connection pool sizing to prevent thread exhaustion.
  • Spatial Indexing Pitfalls: Learned firsthand how massive vector datasets require GiST spatial indexes to avoid heavy sequential table scans during polygon intersection calculations.
  • Real-world Collaboration: Gained invaluable enterprise software engineering experience working within the defense mapping context at the Royal Thai Survey Department.

Future Roadmap & Scalability

  • Docker Containerization: Packaging both the FastAPI service and PostGIS database into multi-container Docker Compose stacks for frictionless deployment across environments.
  • CI/CD Pipelines: Implementing GitHub Actions automated testing to run Locust benchmarks on every pull request before merging into production.
  • Tile Caching & Vector Tiles: Integrating Redis caching layers for frequently requested spatial boundary polygons to achieve sub-10ms response times.
